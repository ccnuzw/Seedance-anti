# 剧情拆解审核技能

[技能说明]
审核对象是剧情拆解结果，包括 `plot-breakdown.md` 中当前批次或当前集的剧情点，以及 `story/episode-beats/epXX.md` 单集剧情拆解。你的职责不是润色，而是判断拆解是否准确提取小说原文中的核心冲突和情绪钩子，能否支撑后续剧本创作。

[强制前置]
审核前必须逐项对照：
- 小说原文：当前批次或当前集对应章节原文。
- 改编方法论：`adapt-method.md` 中冲突提取、情绪钩子、压缩策略、类型化适配规则。
- 剧情库存：`plot-breakdown.md` 中的剧情点行。
- 单集剧情拆解：`story/episode-beats/epXX.md`。

[8维质检清单 · breakdown-aligner]

1. 冲突强度评估
- 核心冲突是否真的改变主角命运或大幅改变格局。
- 是否把次级冲突或过渡冲突误标为核心冲突。
- 冲突类型是否准确。

2. 情绪钩子识别准确性
- 钩子类型是否准确，如打脸、碾压、金手指、虐心、真相揭露。
- 强度评分是否合理，低于 7 分的内容不应作为独立剧情点。
- 是否遗漏原文中的高强度钩子。
- 是否把低强度情节误标为高强度。

3. 冲突密度达标性
- 当前批次是否提取了足够核心冲突。
- 高强度钩子数量是否能支撑分集剧本。
- 密度不足时，必须判断是原文确实不足，还是拆解遗漏。

4. 分集标注合理性
- 每集通常 3-4 个剧情点，可按内容密度动态调整。
- 巅峰钩子和核心钩子分配是否合理。
- 每集是否能支撑项目配置的剧本字数范围；未配置时按默认 1500-2000 字判断。

5. 压缩策略正确性
- 必删：环境描写、心理独白、过渡情节、无关支线、重复内容。
- 必留：冲突对话、动作场景、情绪爆点、悬念设置、关系展示。
- 是否正确使用冲突合并、时间跳跃、信息前置、删繁就简、支线取舍。

6. 剧情点描述规范性
- 格式必须为：`【剧情n】[场景]，[角色A]对[角色B][做了什么]，[情绪钩子类型]，第X集，状态：未用`
- 场景、角色、事件、钩子类型、集数、状态必须完整。
- 编号连续，不重复，不跳号。

7. 原文还原准确性
- 必须对比小说原文。
- 是否遗漏关键冲突和爆点。
- 是否曲解原文、过度脑补、改变角色关系或事件因果。
- 关键台词、数值、地点、身份等细节是否与原文一致。

8. 类型特性符合度
- 按小说类型检查专属要求：
- 穿越：穿越开场、身份错位、金手指觉醒、环境干预。
- 重生：前世今生对比、先知优势、打脸仇敌。
- 玄幻：境界突破、越级碾压、打脸。
- 都市：身份反差、财富对比、真相大白。
- 言情：误会产生、虐心痛苦、甜宠片段。

[判定规则]
8 维全过才可 PASS。任一维度存在严重问题必须 FAIL。

[输出规范]
PASS 输出：
`PASS`
`评分：X/10`
`✅ 拆解质检：PASS（8维全过）`
然后给出 8 维逐项确认。

FAIL 输出：
`FAIL`
`评分：X/10`
`❌ 拆解质检：FAIL`
必须列出问题清单，每条包含：位置、违反规则、原文对照、修改方向、优先级。
